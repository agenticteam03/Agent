The problem the agent solves

    
A container called lab-victim keeps allocating memory past its 128 MiB limit. The Linux kernel kills it (exit code 137, and Docker records OOMKilled=true), Docker's restart policy starts it again, and the cycle repeats. That is incident RB-002 in runbooks/. An engineer on call would read the container's state, decide whether it really is an out-of-memory loop, look closer if unsure, and write down a diagnosis. The agent automates that investigation.

    
Plain Python decides whether there is an incident. A model proposes the next step inside a loop that Python bounds, validates and executes. LangGraph carries one state dictionary through five nodes and merges what each node returns.


    
The one thing to watch

    
A node never edits the state. It returns a small dict, and LangGraph merges that dict into the state after the node has finished. Look for beats marked LANGGRAPH MERGE: they are the only moments the State tab changes. While a node is still running, what it has computed lives in its local variables, shown in a separate cyan box.

Where the toy differs from the real thing

    
Real: the graph, the state, every merge, both routers, the prompt text, Pydantic's checks and the printed output. Fake: FakeMetrics returns fixed numbers, MockLLM replays a script and never reads the prompt, NullDocs finds nothing, NullMemory forgets when the process ends, and the tools only return strings. Three scenarios use the repository's fixtures; docker kill, bad JSON and restart postgres use inputs written for this page, run through the same real code.
